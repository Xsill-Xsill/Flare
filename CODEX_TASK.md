## Task 1 — Vault: items + claims API

### 1a. New API route: `GET /api/v1/vault`

File to create: `app/api/v1/vault/route.ts`

Return a paginated list of items for a workspace with their extracted claims inline.

**Request:**
```
GET /api/v1/vault?workspaceId=<uuid>&limit=20&offset=0&q=<optional search string>
```

**Auth:** same pattern as existing routes — use `createClient()` from `@/lib/supabase/server`, verify user owns workspace.

**Response shape:**
```ts
type VaultItem = {
  id: string
  type: 'text' | 'url' | 'file' | 'audio'
  rawContent: string | null
  sourceUrl: string | null
  status: 'queued' | 'processing' | 'done' | 'failed'
  createdAt: string
  claims: string[]   // statement strings extracted from this item
}

// response: VaultItem[]
```

**Implementation notes:**
- Join `items` → `chunks` → `claims` using Drizzle.
- Only include items with `status = 'done'` when `q` is provided (searching half-processed items is confusing). Without `q`, include all statuses.
- If `q` is provided: filter by `items.rawContent ILIKE %q%` OR `items.sourceUrl ILIKE %q%` OR `claims.statement ILIKE %q%`. Use a single query with LEFT JOINs + DISTINCT on item id.
- Aggregate claims per item in TypeScript after fetching (group by item id).
- Limit max 100.

## Task 2 — Insights: `repeated-problem` detector

### 2a. Detector logic

File to create: `lib/insights/detectors/repeated-problem.ts`

**Goal:** Find when a founder has captured the same problem/pain in 3+ independent items (different `itemId`s). This is the simplest evidence-backed detector.

```ts
export async function detectRepeatedProblems(workspaceId: string): Promise<DetectorResult[]>
```

Where:
```ts
type DetectorResult = {
  title: string        // e.g. "Founders keep losing context between tools"
  summary: string      // 2–3 sentence explanation
  evidence: EvidenceRef[]
}

type EvidenceRef = {
  itemId: string
  claimId: string
  statement: string
}
```

**Algorithm:**
1. Fetch all claims for the workspace (join `claims` → `chunks` → `items` where `items.workspaceId = workspaceId` and `items.status = 'done'`).
2. Group claims by `itemId` — only proceed if there are claims from at least 5 distinct items (otherwise not enough signal).
3. Call Groq to cluster claims into problems:

```
System prompt:
You are analyzing a founder's notes to find recurring problems they keep mentioning.
Given a list of claims (each tagged with an item_id), identify groups of 3+ claims
from DIFFERENT item_ids that describe the same underlying problem.
Return JSON: {"clusters": [{"problem": string, "claim_ids": string[]}]}
Only return clusters where claim_ids span at least 3 distinct item_ids.
If no such clusters exist, return {"clusters": []}.

User message:
<claims>
[{"claim_id": "...", "item_id": "...", "statement": "..."},  ...]
</claims>
```

Use model `llama-3.3-70b-versatile`, `response_format: { type: "json_object" }`, `temperature: 0.1`.

4. For each cluster returned: call Groq again to write the `title` and `summary`:

```
System prompt: You are writing insight summaries for a founder's second brain app.
Be specific and concrete. Title: one sentence (<10 words). Summary: 2-3 sentences explaining the pattern and why it matters.

User message: Problem cluster: <problem>
Evidence claims: <claim statements>
```

5. Return `DetectorResult[]`, one per cluster. Cap at 3 results total (per product rules: no more than 3 insights per digest).

**Error handling:** if Groq fails, log and return `[]` — never throw.

### 2b. Inngest function: `run-detectors`

File to create: `lib/inngest/functions/run-detectors.ts`

```ts
export const runDetectors = inngest.createFunction(
  { id: 'run-detectors', triggers: [{ event: 'detectors/run' }] },
  async ({ event, step }) => {
    const { workspaceId } = event.data as { workspaceId: string }
    // ...
  }
)
```

Steps:
1. `step.run('repeated-problem', ...)` → call `detectRepeatedProblems(workspaceId)`
2. `step.run('save-insights', ...)` → for each result, upsert into `insights` table:
   - Check if an insight with same `workspaceId + detectorType='repeated-problem' + title` already exists (exact title match). If yes, skip (avoid duplicates on re-run).
   - Otherwise `db.insert(insights).values({ workspaceId, detectorType: 'repeated-problem', title, summary, evidence: evidenceRefs })`

Register `runDetectors` in `app/api/inngest/route.ts` alongside `ingestItem`.
